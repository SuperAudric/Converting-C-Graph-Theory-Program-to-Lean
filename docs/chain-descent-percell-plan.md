# PER-CELL CONSUME — the plan for closing `Publication.residue_if_flag`

**Rewritten 2026-08-07** after five probes and a user coverage probe. The 2026-08-06 version
proposed *"per-cell harvest + an all-cells guard, keeping the node-global generator list"*. The
harvest half survives; **the all-cells guard is RETRACTED** (§2). The diagnosis is now sharper, the
design is smaller, and it is measured rather than argued.

> ## ▶ IN ONE PARAGRAPH
> Nothing about the resolver contract or the descent architecture changes. `deepenSupply` is the
> only **pair-anchored** supply in the project — its generators come from deepening pairs drawn from
> one cell — but `SelectNode.cellNarrow` reads a single **node-global** `verified S adj χ` list and
> probes every cell against it. So a cell that never had a descent run on it is judged by
> automorphisms harvested elsewhere, and that verdict is **not relabelling-invariant** (measured, §3).
> The fix is to make the consume half of `cellNarrow` cell-indexed and lazy, exactly matching the
> architecture's own description — *"run the resolver on a cell; if it does not fire, move to the
> next."* `③` is already proved (`RecordDeepen`); the work is `①`'s plumbing and `②`'s numerals.

---

## 1. The core problem, in plain terms

A canonical form must return the same answer for two relabelled copies of one graph.

`selColour` is the object's decision procedure and it is already iso-invariant *in shape*: filter the
non-singleton colours by *"does this cell narrow to ≤ 1?"*, take the minimum. Colour values are ranks
of sorted signatures, hence relabelling-invariant (`nonSingletonColours_transport`), so the order in
which cells are considered is invariant. **All that is required is that each cell's verdict is
invariant.** That is the whole contract, and it is sufficient.

Where the verdict comes from: `cellNarrow key S adj χ c` applies the key first
(`keepMin key adj χ (cellList χ c)`), then maps each survivor to its representative under the group
generated by `verified S adj χ` and dedups. Its **length is the number of orbits meeting the cell**;
length ≤ 1 means "fires".

The key half is per-cell. **The consume half is not.** [`SelectNode.lean:213`](../GraphCanonizationProofs/ChainDescent/SelectNode.lean#L213):

```lean
def cellNarrow (key : Key n) (S : Supply n) (adj) (χ) (c : Nat) : List (Fin n) :=
  cellNarrowV key (verified S adj χ) adj χ c        -- ← one node-global list, every cell
```

That was a deliberate performance decision (the file's own note: phrasing it on `S` re-evaluates the
supply once per probed cell, measured ~10× per node at `n = 14`) and it was **sound for every supply
in the record**: `foldSupply` / `deckSupply` / `deck2Supply` / `kernelSupply` harvest from the whole
graph, so "the generators for this node" is genuinely the right object for them.

`deepenSupply` is the first supply with a **cell of origin**. Its generators are built by deepening
*pairs from the branch cell* — but each one is a full automorphism, so it moves vertices in every
non-singleton cell, and those movements enter the union-find for cells no descent ever visited.

**Measured, CFI cubic m=8 (n=56), at the root:**

| | |
|---|---|
| non-singleton cells | colour 0 (size 32), colour 1 (size 24) |
| branch cell | colour 0 |
| ordered pairs tried | 992 — **all within colour 0**; no cross-cell pair is ever formed |
| verified generators emitted | 320 |
| support per generator | 26–56 vertices moved, of 56 |
| `generator[0]` | moves **20** vertices inside colour 0, **10** outside it |
| orbit blocks read off | colour 0 → `(8,12,12)` · **colour 1 → `(6,6,12)`** |

Colour 1's partition is computed from 320 generators, **not one of which came from a colour-1
descent.**

## 3. THE MEASUREMENTS THAT DECIDE THE DESIGN

All in `scratchpad/`, all comparing a fixed `χ` against **its own transport** — the shape
`cellNarrow_length_transport` is stated in — so no orbit oracle is consulted anywhere and
`probe_orbit_oracle` cannot contaminate them. `twist` carries the `IsColAut` gate, so every generator
counted is verified.

| probe | what it settled |
|---|---|
| `probe_offbranch.py` | root only, 30 witnesses: off-branch counts invariant 30/30. ⚠ **VACUOUS** — the falsifier is deeper |
| `probe_offbranch2.py` | reached nodes, BFS depth 3: ⛔ **REFUTED at depth 1 on all four CFI witnesses** — an off-branch cell of size 2 counts `(1,1)` vs `(2,)` under transport. Branch cell invariant throughout |
| `probe_offbranch3.py` | at that falsifier the **guard is OPEN on both sides** — so this is a real falsifier for `deepenSupplyCert` too, not just the raw supply. (It also independently confirms `tinhofer_iff_certifiedG`: the guard's verdict agreed on both sides everywhere) |
| `probe_offbranch4.py` | **per-cell list repairs it**: A-INV=N → B-INV=Y on all four CFI rows, firing 129/131 and 198/209 cells. ⚠ Not sufficient alone — `rand multipede V=6 W=5` still varies `2` vs `4`, firing 0/8 |
| `probe_offbranch5.py` | **the proposed object holds**: per-cell list **+** per-cell guard, GUARD-INV=Y and COUNT-INV=Y on 9/9, 0 unknowns, 7 rows non-vacuous (open 26/28, 26/28, 18/24, 22/26, 14/14, 10/10, 14/14). On the rigid multipede the guard shuts on all 8 cells, so both sides read `\|cell\|` |
| coverage probe (user, 2026-08-07) | ★ **restriction costs NOTHING**: `A-only = 0` across **646 cells** / 8 witnesses, while `B-only` = 77, 76, 14 on the CFI and MIXED rows. Own-cell evidence strictly dominates borrowed evidence |

**★ The structural fact that makes the design work.** A shut guard emits `[]`, so the count is
`|cell c|` on **both** sides automatically (cells correspond under transport). Therefore the *only*
thing that has to be relabelling-invariant is **the guard's verdict** — never the harvest, never the
partition. That is the per-cell analogue of `tinhofer_iff_certifiedG`, and it is why no completeness
theorem about deepen-as-an-orbit-oracle is needed.

**On borrowed coverage** (user, 2026-08-07). The claim that a `c'`-anchored descent can only tell `c`
a subset of what `c`'s own descent tells it is plausible and measured (`A-only = 0`/646) but is not
obviously a theorem — a `c'`-descent's automorphism acts on `c` incidentally and could connect a pair
that `c`'s own descent misses (i.e. `¬ GoodAnchor` at that pair). **It is not load-bearing**: such
firing happens exactly where `c`'s own guard is shut, and firing on evidence the guard rejects is
precisely the non-invariant behaviour the CFI falsifier exhibits. Borrowed coverage is coverage the
design is not allowed to keep, whether or not the subset claim holds.

## 4. THE DESIGN

**Per-cell, and lazy.** Cell `c`'s verdict is computed from descents on pairs drawn from `c` itself,
gated by `c`'s own guard; cells are consulted in increasing colour order and the first that fires
wins. That is `selColour`'s existing semantics — *the minimum colour that fires* — evaluated lazily,
so it is value-identical, not a redefinition.

Two-sided, and "restriction" is only half of it:

* **EXTEND** — also run descents on pairs from the second cell, third cell, … Today that work is not
  done at all, which is why those cells are judged with no evidence of their own.
* **RESTRICT** — when judging cell `c`, read only the generators that came from `c`'s descents.

⚠ Note what does **not** change: the current harvest already draws pairs only from
`Descend.branches χ` (the lowest-id non-singleton cell) — `deepenGens`'s `p1` and `pj` both range over
`firsts`. **No cross-cell pair is ever formed**, and none should be: different colours ⟹ no
colour-preserving automorphism ⟹ `IsColAut` would reject it. So this was never `n²` comparisons and
is not becoming so.

## 5. THE WORK, ORDERED

Sized against the existing proofs each item mirrors. `③` is **already banked** — see §7.

### W-a. Bill the guard *(small; do this first)*
`deepenSupplyCert` inherits `deepenSupplyGuarded`'s declared flat `n⁶`, which prices deepen but bills
**none** of the certificate (`≤ n` anchors × `≤ n` levels × one `CellIsOrbit` BFS ≈ `n⁸`). This is the
one place the artifact's declared cost is not an honest over-estimate, and every route to `③` passes
through a supply containing it. `DeepenGuard.certPathCost` + `certPathCost_le` already bound it;
`Deepen.stepCost` (2026-08-06) is the worked precedent, including the `ring` re-expansion.
**Do it before `②` becomes a claim that has to be walked back.**

### W-b. Cell-index the supply *(the type change; keep the blast radius controlled)*
Introduce `CellSupply n := AdjMatrix n → Colouring n → Nat → List (Equiv.Perm (Fin n)) × Nat`
alongside `Supply`, with an embedding

```lean
def ofSupply (S : Supply n) : CellSupply n := fun adj χ _ => S adj χ
```

so **every existing supply lifts unchanged** and every existing instance is recovered at `ofSupply`.
`cellNarrow` / `selColour` / `selNode` / `selProbeCost` take a `CellSupply`;
`RecordCost.recordSupplyFast` enters as `ofSupply recordSupplyFast`.

### W-c. Restate the transport obligation *(the bulk, but mechanical)*
Replace `SupplyEquivariant S` in `cellNarrow_length_transport` with the per-cell orbit-transport
property it actually consumes:

```lean
def CellOrbitTransport (S : CellSupply n) : Prop :=
  ∀ (σ : Equiv.Perm (Fin n)) (adj) (χ) (c : Nat), ∀ a ∈ cellList χ c, ∀ b ∈ cellList χ c,
    WordReach (verified (fun a' χ' => S a' χ' c) (relabelAdj σ adj) (transportColouring σ χ)) (σ a) (σ b)
      ↔ WordReach (verified (fun a' χ' => S a' χ' c) adj χ) a b
```

then `selColour_transport` / `nodeTransport_selNode` / `selNode_canonizer` restate against it.
`cellNarrow_length_transport`'s proof already consumes `hS` only through `hmemG'` at pairs inside the
cell, so this is a hypothesis swap rather than a new argument. Prove
`CellOrbitTransport (ofSupply S)` from `SupplyEquivariant S` so nothing existing regresses.

### W-d. The per-cell guard and its completeness *(the one real theorem)*
`CertifiedAt S adj χ c` — the per-cell analogue of `CertifiedG`, quantifying over `cellList χ c`
instead of `Descend.branches χ` — and the per-cell analogue of
`DeepenGuardComplete.tinhofer_iff_certifiedG`. The three ingredients of that proof never mention
*which* cell:

* **fuel adequacy** — `tinhoferPath_fuel_lift`, via the `ncol` measure;
* **spreading** — `tinhoferPath_spread`, from `CellSingleOrbit` at the level;
* **path-local ⟹ all-anchors** — `tinhofer_of_tinhoferPath`.

⚠ One place to check rather than assume: `tinhofer_of_tinhoferPath` uses
`chooseIdK_eq_targetColour` to identify the level's cell with `Descend.branches`. At a non-target
cell that identification is not available, so the per-cell statement must be phrased against
`cellList χ c` directly. **This is the step to scope first** — if it does not go through, the design
still works with a weaker sound-only guard, at the cost of proving invariance another way.

Then generalize `exec_recovers_cell_orbits`: `hr1`/`hrj` are consumed **only** via
`mem_deepenGens_of`, so replacing `Descend.branches χ` with `cellList χ c` is mechanical.

### W-e. Lazy evaluation *(runtime only; semantics unchanged)*
`selColour` is `(nonSingletonColours χ).filter (…) |>.min` — a `Finset` operation, not lazy. Add a
`List.find?`-based computable variant over `nsColours χ` (which already exists as the computable
mirror) plus a `= selColour` lemma. Value-identical; this is purely so the cost story below is real.

### W-f. `②` recompute
`supplyCost_appendSupply` is additive, so appending adds one term to `recordSupplyBound`; then
`RecordKey.recordKeyBound_expand`'s `ring` regenerates `costConst`/`costDeg` (57 / 13 today).
⚠ Numerals are **computed, not fitted** — the 2026-08-06 pass caught a transcription error this way.

### W-g. Repoint `Publication.canonForm?` and discharge `residue_if_flag`
`canonFormFastS?_eq` is `rfl`, so `③` lands directly once the supply is in place.

## 6. ★ COST — the lazy version is cheaper than today's *plus* strictly more coverage

Per cell of size `m`, deepen's harvest is `≤ m` anchors × (one `deepen` at `≤ n` levels × warm refine
`n³`) + `≤ m` replays each `n⁴` + twists at `n²` ≈ **`m² n⁴`**.

* **Worst case** `Σ_c m_c² ≤ (Σ_c m_c)² = n²`, so `≤ n² · n⁴ = n⁶` — **exactly the declared flat
  charge `deepenSupply` already bills**, so `supplyCost … ≤ …` stays `le_rfl` and the per-cell harvest
  costs *nothing* at `②`. The current design's worst case is already one cell of size `n`.
* **Common case, identical to today** — the branch cell fires and no other cell is ever harvested.
* **Extra work only where today's object would stall**, i.e. precisely the nodes that currently flag.
  You pay to try cell 2 only when the alternative was giving up.

⚠ Trap #2's measured 10× does **not** apply: it was re-evaluating the *whole node-global* supply once
per probed cell (`Σ_c Σ_{c'} m_{c'}²`); here cell `c` evaluates only its own harvest.

⚠ The real `②` debts are (a) **W-a**, pre-existing and unrelated to this plan, and (b) re-measuring
any `Regression` number that pins a selected colour — more generators ⟹ `selColour` may commit to a
different (lower) colour. That can only help branching, but it must be measured, not assumed.

## 8. SCOPING DECISIONS

* **Decouple `pairStep`.** It builds no supply, and its pair caveat (§9) is a live design question.
  Per-cell consume is what closes `residue_if_flag`; `pairStep` and `GoodOrIsolated` are coverage
  wideners that compose afterwards. Bundling them makes an open design question block the
  publication close.
* **Stay at the fused object.** The blind guarded object needs only branch-cell transport
  (`SameOrbitsOnBranches` already exists for it) and `deepenSupplyCert_canonizer` is already proved
  there — but it is dominated value-exactly by `selNode`, and `Publication`'s `①`/`②` are already
  unconditional at the fused object. Repointing would re-open both.
* **Do not close a `Publication` obligation at a second object.** Standing steer; tried and reverted
  2026-08-04.

## 9. ⚠⚠ THE PAIR CAVEAT — retained, demoted to `pairStep`'s own scoping

Recorded because it bounds what a per-*cell* predicate can express, and it becomes live the moment
`pairStep` gets a supply.

`pairStep` is indexed by an ordered **pair**, and pairs from the same cell are not interchangeable.
`C₆` is minimal (`DeepenPair` §C₆): vertex-transitive, so all six vertices are one cell and one
orbit — yet the distance-2 pair `(0,2)` discretizes with **zero** further decisions while the adjacent
pair `(0,1)` costs an extra individualization. The natural index for the pair object is the
**orbital**, not the cell — the orbits-vs-orbitals seam that separates 1-WL from 2-WL throughout this
project. A pair-based guard written per-member and *assumed* to cover pairs would be
unsound-by-omission.

⚠ This does **not** apply to §4's design, which is indexed by cells and uses the existing single
`step`.

## 10. RISKS

1. **W-d's per-cell completeness may not go through** at a non-target cell (the
   `chooseIdK_eq_targetColour` step). Scope it before writing W-b/W-c. Fallback: a sound-only
   per-cell guard plus a separate invariance argument — weaker, and worth knowing early.
2. **Counts here are key-free.** `cellNarrow` applies `keepMin key` before counting, so a key that
   separates a small cell could mask a specific discrepancy. That is not a defence — the discrepancy
   lives in the supply — but the positive rows in §3 should be re-confirmed at `recordKey` before
   they are quoted as coverage.
3. **Probe scope.** §3's falsifier is at depth ≤ 3 with 3–4 relabellings; being a *falsifier* that is
   enough. The **positive** rows carry the usual caveat: a family-level claim needs every reached
   node, and `probe_offbranch5` ran at depth 1.
4. **`BAD-BIG = 0` is falsified** (`DeepenComplete` §5.2), so good-or-rigid does not cover everything
   reachable. The per-cell guard will shut at mixed-cell nodes — sound, but it caps what the widening
   can be expected to buy.
